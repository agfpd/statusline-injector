# statusline-injector

> Хук для Claude Code, который показывает LLM-агенту его собственный
> живой статус на каждом ходе: время, модель, токены сессии,
> заполненность контекстного окна и расход подписки.

**Платформы:** macOS, Linux.

## Проблема: агент, который не видит часов

По умолчанию LLM-агент, работающий внутри Claude Code, не знает
- сколько сейчас времени,
- какая именно модель обслуживает этот ход (`opus-4-6` и
  `opus-4-6[1m]` — разные контекстные окна),
- сколько токенов уже потратила текущая сессия,
- насколько заполнено контекстное окно,
- насколько близко 5-часовой или 7-дневный лимит подписки Pro/Max
  к сбросу.

Хостовый процесс Claude Code всё это знает. Агент — нет. Пока
эту информацию ему явно не положат в контекст.

Результат предсказуемый: агент планирует как будто время
бесконечно, продолжает грузить материалы в контекст, заполненный
на 85%, и удивляется, когда длинная задача умирает посреди работы
из-за того, что 5-часовое окно только что закрылось.

## Что делает инструмент

Два маленьких шелл-скрипта:

1. **`statusline-state-writer.sh`** — регистрируется как команда
   `statusLine` в Claude Code. Хостовый процесс передаёт ему JSON
   со состоянием на stdin перед каждым ходом. Скрипт атомарно
   сохраняет этот JSON в файл (по умолчанию
   `~/.claude/statusline-injector/state.json`) и печатает короткую
   однострочную сводку для терминального UI.

2. **`statusline-injector.sh`** — регистрируется как хук
   `UserPromptSubmit`. На каждом пользовательском ходе читает live
   JSONL-транскрипт (токены, модель, размер контекста) и
   сохранённое состояние (лимиты подписки), собирает статус-блок
   и печатает его в stdout. Claude Code добавляет этот stdout в
   контекст агента.

Агент видит в начале каждого хода примерно такой блок:

```
[status @ 2026-04-15 18:24 +0300]
- model: claude-opus-4-6[1m]
- session: ↓12.3k / ↑4.1k tokens
- context: 8.1% of 1000k window
- subscription: 5h 5% (resets 23:00) / 7d 34% (resets 17.04)
```

Когда расход подписки пересекает порог, строка получает маркер:
`⚡` на 70% (watch), `⚠️` на 85% (close), `🔴` на 95% (critical).
Пороги настраиваются.

## Быстрый старт

> Требуется: `bash`, `jq`, `awk`, `date`, `printf`.
> На macOS: `brew install jq`. На Debian/Ubuntu: `apt install jq`.

```sh
git clone https://github.com/agfpd/statusline-injector.git
cd statusline-injector
./install.sh
```

Установщик — небольшой интерактивный мастер. Спрашивает, какие
поля показывать, какие пороги использовать, куда сохранять файл
состояния, и предлагает автоматически прописать оба хука в
`settings.json` Claude Code (с бэкапом с таймштампом). Можно
пропустить регистрацию и вставить показанный сниппет вручную.

После первого перезапуска Claude Code статус-блок начинает
появляться в контексте агента.

## Конфигурация

Всё поведение управляется переменными окружения. Установщик
записывает их в `~/.claude/statusline-injector/config.env`; хуки
сорсят этот файл перед запуском.

```sh
# Где statusline-state-writer.sh сохраняет состояние между ходами
STATUSLINE_STATE_FILE="$HOME/.claude/statusline-injector/state.json"

# Заголовок, показываемый как [<title> @ YYYY-MM-DD HH:MM ±TZ]
STATUSLINE_TITLE="status"

# Включение/выключение отдельных полей (1 = показать, 0 = скрыть)
STATUSLINE_SHOW_TIME=1
STATUSLINE_SHOW_MODEL=1
STATUSLINE_SHOW_SESSION=1
STATUSLINE_SHOW_CONTEXT=1
STATUSLINE_SHOW_SUBSCRIPTION=1

# Пороги предупреждений для строк подписки (% использования)
# 70% → ⚡ watch    85% → ⚠️ close    95% → 🔴 critical
STATUSLINE_WATCH_5H=70
STATUSLINE_WARN_5H=85
STATUSLINE_CRIT_5H=95
STATUSLINE_WARN_7D=85
STATUSLINE_CRIT_7D=95
```

Редактируйте файл напрямую или перезапустите `./install.sh`, чтобы
пересоздать его.

## Архитектура

Две ответственности, разнесённые в два скрипта:

- **`statusline-state-writer.sh`** владеет единственным полем, до
  которого UserPromptSubmit-хук сам не дотянется: `rate_limits`
  (счётчики подписки Pro/Max) и точный id модели с суффиксом
  `[1m]`. Хостовый процесс передаёт их только через канал
  `statusLine`. Скрипт делает одну задачу — атомарно сохраняет
  JSON, чтобы injector никогда не прочитал файл на половине записи.

- **`statusline-injector.sh`** — слой представления. Читает путь к
  JSONL-транскрипту, который передал хостовый процесс, и
  вычисляет токены сессии и размер контекста последнего хода из
  записей `message.usage` (`input_tokens + cache_read +
  cache_creation`, потому что cache_read тоже считается в то, что
  модель фактически видит). Контекстное окно берётся по id модели:
  `[1m]` → 1 000 000, всё остальное → 200 000.

Существенные детали:

- `LC_ALL=C` устанавливается принудительно — под локалью вроде
  `ru_RU` `awk`/`printf` выводят десятичные дроби с запятой, и
  проценты ломаются.
- Запись файла состояния идёт через `mktemp` + `mv` — атомарно.
- Injector завершается с кодом 0 даже при отсутствии `jq` или
  файла состояния: статус-блок — «приятный бонус», не повод
  блокировать ход.

## Что это НЕ

- **Не телеметрия.** Ничего не покидает машину. Файл состояния
  живёт под `$HOME`.
- **Не планировщик и не ограничитель.** Не блокирует ходы, не
  тормозит агента, не ставит работу на паузу. Только показывает
  информацию, на которую агент может реагировать — что делает с
  ней агент, зависит от его системного промпта.
- **Не token-precision.** Процент контекста выводится из последней
  записи `usage` в транскрипте; во время насыщенного
  tool-вызовами хода значение отстаёт на один шаг. Достаточно для
  решений «я приближаюсь к границе окна», недостаточно для
  точного бюджетирования.

## Зачем это нужно

Представь человека, который не знает который час, утро сейчас или
вечер, давно ли длится разговор, сколько у него осталось сил.
Он может быть умным, но не может быть уместным — ему не от чего
оттолкнуться.

LLM-агент по умолчанию ровно такой. Каждая реплика собрана из
вакуума: нет референса к ситуации. Дать ему часы, ощущение
«сколько я уже работаю» и «сколько ресурса осталось» — это не
косметика, это перевод его из генератора текста в собеседника,
способного читать момент.

Что тогда становится возможным:

- адаптировать тон под время суток,
- предупредить пользователя, что 5-часовая подписка подходит к
  границе — пока ещё есть время свернуть задачу,
- заметить, что контекст заполняется, и предложить `/clear` или
  сузить объём — до того, как компакция обрежет рабочую память,
- почувствовать, что разговор буксует, и сменить подход.

Эти поведения всё равно надо прописать в инструкции агента —
статус-блок только доносит информацию. Но без этой информации их
не существует в принципе: сигнал физически не доходит до модели.
