# statusline-injector

**Plug-and-play плагин для Claude Code и Codex CLI: инжектит агенту его собственный живой статус в контекст на каждом ходу.**

Инжектнутый статус — одна минимальная строка: системное время, лимиты подписки 5h/7d и заполнение окна контекста.

**Платформы:** macOS, Linux. **Рантаймы:** Claude Code, Codex CLI.

## Проблема: агент, который не видит часов

По умолчанию LLM-агент не знает
- который сейчас час,
- насколько уже заполнено его окно контекста,
- как близко подписка Pro/Max (или ChatGPT) к сбросу 5-часового или 7-дневного окна.

Харнес знает всё это. Агент — нет, пока ему явно не положат это в контекст.
Итог предсказуем: агент планирует так, будто время бесконечно, грузит материал
в контекст, уже заполненный на 85%, и удивляется, когда долгая задача обрывается
на полпути — 5-часовое окно только что захлопнулось.

## Что видит агент

Одна строка, в начале каждого хода. Часы есть всегда; контекст и лимиты подписки
появляются, только когда начинают иметь значение — каждый показывается, лишь
перевалив за половину своего бюджета, и то голым числом, без тревоги. На здоровом
ходу это вся строка:

```
[st 14:30+03]
```

Как только окно контекста или окно лимита заполняется за 50%, его сегмент
появляется — по-прежнему голым фактом:

```
[st 14:30+03 · ctx 150k/200k · 5h 62%]
```

- `st HH:MM±TZ` — системное локальное время со смещением системной таймзоны
  (не хардкодится; фолбэк — UTC). **Показывается всегда.**
- `ctx used/window` — заполнение контекста числом токенов к размеру окна
  (например `150k/200k`, `620k/1m`). Показывается, только когда заполнение
  перевалит за 50% окна.
- `5h` / `7d` — два окна лимитов подписки, процент израсходованного. Каждое
  показывается, только когда перевалит за 50%.

Метрики намеренно тихие. Ниже половины они скрыты полностью; выше — голые числа,
без обратного отсчёта до сброса, без маркера-предупреждения, не на чём
зацикливаться. Цель — сигнал, на который агент реагирует у границы, а не
счётчик, который он проговаривает каждый ход. И строка крошечная по замыслу: на
Claude инжектнутый контекст копится в транскрипте ход за ходом, поэтому каждый
токен, сэкономленный ниже порога, — повторяющийся налог, снятый со всего флота.

## Зачем это нужно

Агенту, который не видит часов и остатка бюджета, не от чего оттолкнуться. Дайте
ему и то и другое — и он сможет действовать: предупредить пользователя, что
5-часовое окно подходит к пределу, пока ещё есть куда посадить задачу; заметить,
что контекст заполняется, и предложить сузить объём до того, как компактизация
срежет рабочую память; подстроиться под момент.

Каждое из этих поведений живёт в инструкциях самого агента — строка статуса лишь
поставляет данные. Без неё они невозможны: сигнал не доходит до модели.

## Установка

Распространяется через marketplace `agfpd`. Установка plug-and-play — без ручных
шагов и пост-установочной возни.

**Claude Code** (project scope):

```sh
claude plugin marketplace update agfpd
claude plugin install statusline-injector@agfpd --scope project
```

**Codex CLI** (глобально — Codex применяет плагины на весь хост):

```sh
codex plugin marketplace upgrade agfpd
codex plugin add statusline-injector@agfpd
```

Перезапустите сессию (или `/reload-plugins` в интерактивном Claude Code) — и
строка начнёт появляться на каждом ходу. Project scope удобен для пробы: если
передумали, скилл [`statusline-uninstall`](#удаление) откатит весь цикл — он
трогает только строку-команду `statusLine`.

> Нужен `jq` в `PATH`. macOS: `brew install jq`. Debian/Ubuntu: `apt install jq`.
> Если `jq` нет — плагин тихо деградирует и никогда не блокирует ход.

## Как это работает

Рантаймы отдают данные по-разному, поэтому плагин читает каждый из своего источника.
Инжектнутая строка — одинаковая.

| Данные | Claude Code | Codex CLI |
|---|---|---|
| Время | системные часы, системная TZ | то же |
| Контекст / окно | blob statusLine (`context_window`), фолбэк — транскрипт | роллаут `token_count` (`last_token_usage.input_tokens` / `model_context_window`) |
| Лимиты 5h / 7d | **только** stdin команды `statusLine` (пуш харнеса) | роллаут `token_count` (`rate_limits.primary` / `secondary`) |

**Claude — обернуть, не заменить.** Лимиты `rate_limits` входят в систему ровно
одним каналом: JSON, который харнес шлёт команде `statusLine` на stdin. Их нет ни
в транскрипте, ни в файлах. Поэтому хук `SessionStart` идемпотентно **оборачивает**
project-scope `statusLine.command`: обёртка захватывает blob в per-session
state-файл, затем прокидывает тот же stdin в оригинальную команду пользователя и
возвращает её stdout без изменений — терминальная строка пользователя сохраняется
нетронутой. Хук `UserPromptSubmit` читает state-файл и рисует строку. Обёртка
обратима и никогда не правит содержимое скрипта пользователя — только строку-команду
в `settings.json`.

**Codex — без обёртки.** Всё (лимиты и контекст) уже лежит в роллауте сессии,
поэтому тот же хук `UserPromptSubmit` читает его напрямую. Перехвата statusLine нет.

## Конфигурация

Через env-переменные (все необязательны):

```sh
# Где лежат per-session state + стабильная обёртка (Claude).
STATUSLINE_STATE_DIR="$HOME/.claude/statusline-injector"

# Процент бюджета метрики, выше которого она появляется в строке. Ниже — контекст
# и лимиты 5h/7d скрыты; часы показываются всегда.
SL_SHOW_PCT=50
```

## Удаление

Обёртка Claude полностью обратима. Попросите агента «uninstall
statusline-injector» или «revert the statusline wrap» — встроенный скилл
`statusline-uninstall` (работает в обоих рантаймах) восстановит оригинальный
statusLine. Либо запустите скрипт напрямую:

```
bash "$CLAUDE_PLUGIN_ROOT/scripts/statusline-uninstall.sh" [settings.json]
```

Он восстанавливает оригинальный statusLine (или убирает нашу строку, чтобы
харнес сам упал на нетронутый user-scope). В Codex обёртки нет — там реверту
нечего. Затем уберите сам плагин: `claude plugin uninstall statusline-injector`
/ `codex plugin remove`. Обёртка к тому же само-деградирует — она продолжает
отдавать ваш оригинальный statusLine, даже если плагин удалён без реверта.

## Чем это НЕ является

- **Не телеметрия.** Ничего не покидает машину. State лежит под `$HOME`.
- **Не планировщик и не лимитер.** Никогда не блокирует ходы и не тормозит
  агента; только показывает информацию, на которую агент может реагировать.
- **Не точно до токена.** Контекст отстаёт на один шаг во время tool-heavy хода —
  достаточно для «приближаюсь ли к окну», но не для точного бюджетирования.
